# Stage: audio-finalized

Build the output-timeline subtitle track, normalize loudness, and lock
the audio chain before render.

## Entry condition

- `manifest.stage == overlays-applied` (or `cuts-extracted` if no overlays)

## What to do

### 1. Build master.srt with output-timeline offsets (Hard Rule 5)

For each word in the WhisperX transcript that falls inside a kept
range, compute:

```
output_time = word.start - range.start + range_offset_in_output
```

where `range_offset_in_output` is the sum of preceding range
durations in the EDL. Write the SRT to `edit/master.srt`.

Source-time offsets are WRONG. The renderer expects output-time.

### 2. Pick a subtitle style

`manifest.subtitles.style` selects a preset for the **drawtext** burner.
Default = `drawtext-bold-lower-third`. Available presets (see
`/opt/claude-config/tools/burn-subtitles --style`):

| Preset    | Use                                                |
|-----------|----------------------------------------------------|
| `cinema`  | white on translucent black, lower third (default)  |
| `news`    | white on opaque black, lower third (legibility)    |
| `kinetic` | yellow on translucent black, larger boxborder      |

Chunk into 2-word UPPERCASE segments for short marketing cuts; 4-7 word
sentence case for narrative content.

**Why drawtext, not the ASS `subtitles` filter**: smoke testing caught
the ASS path silently ignoring its PlayResY anchor when output canvas
disagreed (1080×1920 vertical vs. PlayResY=288), so a caption at
"FontSize=18" rendered at ~40% of frame height. drawtext takes pixel
sizes that scale directly with output height. The ASS path is still
available via `--engine ass` on the wrapper if a specific delivery
requires it (rare).

### 3. Audio normalize (loudnorm)

Run two-pass EBU R128 loudnorm via
`agents/Claude-Video-Editor-Plugin/skills/normalize-audio/`. Target:
- YouTube: -14 LUFS, -1 dBTP
- Broadcast: -23 LUFS, -1 dBTP
- Podcast: -16 LUFS, -1 dBTP

Read target from `manifest.audio.target` or default to -14 LUFS.

Apply to the EXTRACTED clips (per-segment) so the master concat is
already normalized.

### 4. Optional voiceover

If the strategy calls for a generated voiceover and `manifest.voiceover`
is populated:
- Generate via local TTS (F5-TTS or XTTS v2). Install via
  `agent-install` if not present.
- Save to `edit/voiceover/<n>.mp3` per scene.
- Reference in the EDL `overlays[]` for compositing during render.

### 5. Music — mode-aware, variant-routed

Music workflow is governed by `manifest.music.mode` (set during
`/inventory`'s brief-derivation pass or `/music` selection):

| Mode | Bake into which variant |
|---|---|
| `baked-royalty-free` | `platform_final` |
| `baked-licensed` | `platform_final` (requires `license_proof`) |
| `internal-reference` | `internal_review` ONLY (never `platform_clean`) |
| `none` | none |

**Hard rules for the two-variant pattern** (Reels / TikTok / IG-style
platforms where marketing adds music in the platform UI):

1. `<slug>_INTERNAL_REVIEW.mp4` — picture lock + dialogue + sfx + ambient + **proposed music baked at sidechain duck** (-12dB under dialogue, -18dB safer). This is the marketing-review artifact. Source for the music can be royalty-free OR a YT-mp3 reference (per `fsh-royalty-free-music` § Mode 2). Filename suffix `_INTERNAL_REVIEW` is non-negotiable.
2. `<slug>_CLEAN_FOR_UI_MUSIC.mp4` — picture lock + dialogue + sfx + ambient ONLY. **No music stem.** This is what marketing uploads to the platform muted; they add the licensed track in the IG / TikTok music editor using the timecodes in `docs/music_cues.md`. Filename suffix `_CLEAN_FOR_UI_MUSIC` is non-negotiable.
3. `docs/music_cues.md` — generated by `/opt/claude-config/tools/music-cues-template <slug>`. This is what makes the clean variant usable by marketing. Without it, they can't replicate the proposed sync.

Apply sidechain ducking via:
```bash
ffmpeg -i base.mp4 -i music.mp3 \
  -filter_complex "[1:a]volume=0.30[mlow]; \
                   [0:a][mlow]sidechaincompress=threshold=0.05:ratio=8:attack=5:release=200[mixed]" \
  -map 0:v -map "[mixed]" -c:v copy -c:a aac -b:a 192k \
  <slug>_INTERNAL_REVIEW.mp4
```

For platforms NOT using the IG-style add-music-in-UI pattern (YouTube
long-form, Shorts, LinkedIn, broadcast), only `platform_final` is
produced — music baked. No two-variant split needed.

Verify with `ffprobe`:
```bash
# Clean variant must have NO music: peak under speech-only voice levels
ffprobe -v error -of csv=p=0 -show_entries stream=codec_type \
  <slug>_CLEAN_FOR_UI_MUSIC.mp4 | sort -u
# expected: audio, video — and audio loudness within speech band
```

## Gate

```bash
/opt/claude-config/hooks/pipeline-gates.sh "<id>" audio-finalized
```

Must exit 0. `master.srt` must exist.

## `manifest.stage = audio-finalized`. Commit.

## Pitfalls

- **Source-time offsets in SRT.** Captions drift after segment concat.
  ALWAYS output-time (Hard Rule 5).
- **Subtitle text overlap with overlays.** Verify in self-eval stage.
  Subtitles render LAST in the filter chain (Hard Rule 1) but if
  `MarginV` puts them where an overlay sits, they collide.
- **Loudnorm in single pass.** Single-pass loudnorm is approximate;
  always two-pass for delivery.
- **TTS sample rate mismatch.** Generate at 48kHz to match video audio.
- **Music too loud.** -12 dB sidechain duck under speech is the floor;
  -18 dB is often better. Test with self-eval timeline_view + waveform.
